# Liquid Motion アプリ設計ギャップ提案

Status: Proposal only  
Scope: 実装変更なし。今後の実装順序と受け入れ条件を定義する。  
Baseline: main ブランチ

## 目的

Liquid Motionを、単一のランダムな物理デモから、上下反転して繰り返し遊べるデジタル鑑賞玩具へ発展させるための設計上のギャップを整理する。

現行コードはCanvas 2D、自作パーティクル物理、端末の傾き入力、反転用の重力変更、手続き生成された段差・羽根車・シーソーまで実装している。本提案は、その動きを置き換えるものではなく、アプリとしての再現性・操作性・拡張性を補うものである。

## 現行コードの確認結果

| 領域 | 現在の実装 | 状態 |
| --- | --- | --- |
| 描画 | Canvas 2D。液滴は低解像度オフスクリーンCanvasで描画 | 実装済み |
| 物理 | Verlet積分、近傍探索、凝集・反発・粘性、壁・部品との衝突 | 実装済み |
| 入力 | DeviceOrientation、iOS権限要求、反転ボタン、ダブルタップ | 一部実装 |
| ステージ | `level.js`で段差、トレイ開口、羽根車、シーソーをランダム生成 | 一部実装 |
| アプリ状態 | `main.js`の`running`による再生・停止のみ | 不足 |
| シーン | 固定シーンやシーン選択はなく、リサイズ・リセットごとに再生成 | 不足 |
| 流体 | 粒子としての主液体と、描画上の周囲媒体。液体種別は1色 | 不足 |
| ギミック | 羽根車・シーソーは粒子衝突と重さで動く。歯車間の連動や弁はない | 不足 |
| 保存・共有 | 保存、URL共有、JSONシーン定義はない | 未実装 |

既存のPR #4は、ジグザグ階段と粘性調整による実物玩具らしさの改善を目的としている。本提案はPR #4と競合しないアプリ設計・データモデル・品質保証の整理である。

## 解消すべきギャップ

### 1. ランダムなデモから再現可能な玩具シーンへ

現行の`Math.random()`による生成では、同じシーンを再表示できず、修正前後の比較や共有ができない。リセットもシーンの再生成を意味している。

提案:

- シーンをJSONで定義する
- `seed`付き乱数を導入する
- シーン構造と初期状態を分離する
- リサイズではシーンを再生成せず、座標を再投影する
- リセットは同じシーン・同じseedの初期状態に戻す
- ランダムシーンは固定シーンとは別の実験モードに分ける

### 2. `running`一つの状態から明示的な状態機械へ

現在は`running`の真偽だけで、反転中、流れが落ち着いた状態、リセット中、センサー未許可などを表現できない。

最低限、次の状態を定義する。

- `ready`
- `running`
- `paused`
- `settled`
- `flipping`
- `resetting`
- `unsupported-input`

状態遷移と操作をシミュレーション層に集約し、UIや入力方式が変わっても物理状態が壊れないようにする。

### 3. 反転を重力変更だけでなく玩具の動作として表現する

現行の`OrientationInput.flip()`は重力ベクトルを180度回転させるが、容器そのものの回転演出や反転完了後の状態遷移はない。画面上では、ユーザーが容器をひっくり返した結果が十分に伝わらない。

提案:

- 反転開始時に`flipping`へ遷移する
- 0.4〜0.8秒程度でシーン全体を180度回転する
- 回転中は入力と物理更新を制御する
- 回転完了後に重力方向と流体の流れを再開する
- 端末センサー、ボタン、ダブルタップを同じ反転コマンドへ統合する

### 4. 物理モデルを玩具用の流体モデルとして明文化する

現在は粒子群が一つの色で描画され、周囲媒体は主に浮力・抵抗・背景描画として扱われている。これは見た目のプロトタイプとしては有効だが、「複数の混ざりにくい液体」をシーンとして扱うデータモデルにはなっていない。

提案:

- 流体を`id`、色、比重、粘度、凝集、表示方法で定義する
- 流体量をシーンの状態として追跡する
- 液体の保存則を厳密なCFDではなく、体積・通路・タンク単位で保証する
- 液滴表現と液体量の計算を分離する
- 現行の粒子物理は、第一段階では視覚表現用の近似モデルとして維持する
- 厳密な流体力学シミュレーターを目標にしない

### 5. ギミックを衝突物体から機構ネットワークへ

現行の羽根車とシーソーは粒子衝突によって動くが、部品同士の連動、弁の開閉、分岐・合流のルールは表現されていない。

提案:

- 部品に入力ポートと出力ポートを持たせる
- 液体流量または接触量をイベントとして扱う
- 羽根車、歯車、弁、シーソーを別々のコンポーネントとして定義する
- 歯車の回転比と回転方向を定義する
- 一定量の液体で弁が開くなど、しきい値ルールを定義する
- 物理演算と機構ルールを分離し、ルールをテスト可能にする

### 6. 玩具としての操作性を補う

現行UIは開始、反転、リセットに限定されている。要件定義で想定した鑑賞玩具としては、一時停止、速度変更、状態の再現、入力方式の切り替えが必要である。

追加する操作:

- 再生 / 一時停止
- リセット
- 反転
- 速度 0.5倍 / 1倍 / 2倍
- センサー入力の有効・無効
- 音の有効・無効
- シーン選択

### 7. Webアプリとしての配布要件を埋める

現在はGitHub Pagesへ静的デプロイできるが、インストール可能なWebアプリとしての定義がない。

提案:

- `manifest.webmanifest`を追加する
- Service Workerで固定アセットをキャッシュする
- オフラインで固定シーンを再生できるようにする
- アイコン、テーマカラー、表示名を定義する
- センサー非対応環境でもボタン操作だけで遊べるようにする
- Canvas非対応時の代替メッセージを表示する

### 8. アクセシビリティと入力安全性を追加する

現行では、ページ全体の`touchmove`をキャンセルしており、キーボード操作、モーション軽減、スクリーンリーダー向けの状態説明もない。

提案:

- `prefers-reduced-motion`に対応する
- 反転、再生、一時停止、リセットにキーボードショートカットを設定する
- ボタンに視覚的なラベルとフォーカス表示を持たせる
- 色だけで流体や状態を区別しない
- `touchmove`の抑制範囲をキャンバス内に限定する
- センサーが利用できない場合の説明を表示する
- 一時停止を常に利用できるようにする

### 9. 自動テストと性能確認を追加する

現在のActionsはGitHub Pagesへのデプロイが中心で、物理や入力の回帰を検出できない。

最低限の検証対象:

- シーンseedが同じ場合、同じ初期配置になる
- 180度反転でシーンの対称性が保たれる
- 一時停止中に物理状態が変化しない
- リセットで初期状態に戻る
- リサイズでシーンが意図せず再生成されない
- センサー非対応環境でボタン操作が利用できる
- 低性能端末でフレーム時間と粒子数を計測できる
- `prefers-reduced-motion`時に自動反転演出を抑制できる

## 推奨実装順序

### Phase 1: シミュレーション契約

- シーンJSONの型を定義する
- seeded randomを導入する
- 状態機械を導入する
- reset / pause / resume / speedを追加する
- リサイズとリセットを分離する

### Phase 2: 反転と入力

- 反転アニメーションを実装する
- センサー、ボタン、ダブルタップを統合する
- センサー未対応・権限拒否時のフォールバックを整える
- キーボードとモーション軽減に対応する

### Phase 3: シーンと機構

- 固定シーンを3種類定義する
- Step Drop、Gear Flow、Branch and Mergeを作成する
- 歯車連動、弁、分岐、合流をコンポーネント化する
- 視覚的なランダムシーンは実験モードとして残す

### Phase 4: 配布と品質

- PWA manifestとService Workerを追加する
- ローカル保存とJSONエクスポートを追加する
- 物理・状態・入力のユニットテストを追加する
- ブラウザ操作テストと性能計測をActionsへ追加する

## このproposalの受け入れ条件

- このPRではランタイムコードを変更しない
- 現行実装と要件定義の差分がファイル単位で追跡できる
- 実装順序と各段階の完了条件が明示されている
- PR #4の視覚・粘性改善と責務が重複していない
- 後続実装が、ランダム生成の追加修正ではなく、シーン・状態・機構の契約に基づいて進められる

## 対象外

- 完全な流体力学計算
- サーバー、認証、ランキング
- ユーザー作成シーンの公開基盤
- 音響演出の作り込み
- 3D・VR・ARレンダリング

これらはシーンモデル、状態機械、入力、テスト基盤が固まった後に判断する。
